# Make configuration export transactional

Maintain the existing `rust-atomic-export export DEST` command. It currently truncates DEST before validating the input. Harden the write lifecycle so failed exports preserve previous files, with successful output remaining byte-for-byte compatible. Evaluation runs on Linux with ordinary local files; symlinks, concurrent writers, successful directory replacement, and cross-filesystem destinations are out of scope. An existing directory at DEST is a supported failure case: the attempted rename must fail with a `commit` diagnostic, preserve the directory contents, and remove this invocation's temporary file.

Read stdin as `key<TAB>value` records, skipping empty physical lines. Keys contain one or more ASCII letters, digits, `_`, or `-`; values may be empty or contain spaces, but no tabs. Neither field is trimmed. Duplicate keys use the last value. Serialize distinct keys in Rust string order as `key<TAB>value` newline records. Success replaces DEST with the complete serialized content (including an empty file for empty input), prints `EXPORTED<TAB>distinct-key-count` plus newline, and exits 0. Relative paths resolve from the process working directory; existing parent directories are required.

Parse and validate all input before opening any output file. Stage the complete output at the exact sibling path `DEST.tmp` using exclusive creation, close it, then rename it over DEST. If `DEST.tmp` already exists, fail without modifying either file. Remove a temporary file created by this invocation if a later write/rename step fails; never remove a preexisting temporary file. Success leaves no temporary file. Do not delete or truncate DEST before the rename. The required guarantee covers errors during this invocation; crash and power-loss durability are outside scope.

Any failure exits 2 with empty stdout and `error:` stderr. Invalid input must identify physical `line N`; a temporary-file creation error contains `temporary`; rename failure contains `commit`; incorrect arguments contain `usage`. Failed validation must preserve DEST byte-for-byte (or keep it absent), and must not create DEST.tmp. Do not add backups, locks, permissions management, network access, or dependencies.

Work only in `src/` and `tests/`. Keep the CLI contract and existing public behavior. Use Rust 1.95 and the standard library; do not add dependencies or modify Cargo metadata. The project is deliberately detached from the parent workspace. Run `just test` in the project (with an isolated `CARGO_TARGET_DIR`) to execute its public tests. No network, services, clock, or environment configuration is needed. Input sizes are modest; do not add unrelated features.
