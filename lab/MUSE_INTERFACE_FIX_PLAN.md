## Critique and refinements

- Context contributors operate at turn boundaries and generic tool-finish callbacks cannot rewrite shell results. A private lookup tool uses existing extension surfaces and avoids adding upstream hooks or changing the shell output protocol.
- Prompt wording alone cannot establish that a provider-generated call ID is visible to the model. A receipt makes the identifier explicit, while the existing final join supplies authority. Do not weaken that join to accept chunk IDs or implicitly select the last successful command.
- Indexed lookups keep each response small without a general pagination framework, history rewrite or extra host-controlled model loop. Failed/unfinished observations remain distinguishable. This is a command-reference interface, not a new evaluator.
- Host-issued command previews are still untrusted task data, represented as JSON values and explicitly identified as previews. Receipt bounds prevent a new oversized context item. Existing full command/tool evidence remains the source for review.
- New tool calls and planner wording change the experimental condition. Effective metadata versions, binary digests and captured phase inputs record that change. Do not compare this run with v1 as if representation alone changed.
- No inherited workflows or v1 skills need mutation: the observed mistakes concern the runtime report contract, so procedural variants would conflate unrelated dimensions. A generic policy bus, retries, benchmark runner and UI remain deferred.
